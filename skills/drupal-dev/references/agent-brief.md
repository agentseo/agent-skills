# Бриф субагенту на Drupal-задачу

Субагент знает только бриф. Шаблон (заполнить, лишнее убрать):

```
Задача: <что сделать, критерий готовности>. Бид/карточка: <id>.

Где работать:
- твой стенд tN: каталог <путь к стенду>/<ddev-подкаталог>, ddev-проект <имя>-tN, ветка <ветка>;
  создан основной сессией (или: создай `stand.sh create N` из <основное дерево>);
- основное дерево и чужие стенды не трогать; коммить в свою ветку, не пушить, не мержить.

Доступы:
- dev и прод — только чтение / запрещены (как в AGENTS.md проекта); дампы БД не заливать;
- секреты — только через механизм проекта, значения не печатать.

Тесты (навык drupal-dev, references/testing.md):
- по ходу: `test.sh <модуль>` (Unit+Kernel) из каталога стенда;
- в конце один раз: `test.sh <модули> --full`;
- новые тесты — Unit/Kernel/Functional; ExistingSite только для сайта, никогда против прода.

Код: <версия ядра / ^10.3 || ^11>; правила — references/d11-practices.md; phpcs Drupal +
DrupalPractice и phpstan проекта без новых замечаний.

Стоп-условия: <что требует вопроса владельцу> — остановиться и сообщить, не обходить.

Отчёт (коротко):
1. что сделано — коммиты (SHA, одна строка каждый) и изменённые файлы;
2. тесты — команды и итог (классов/методов, время, упавшие);
3. что не сделано или под вопросом, что проверено только частично;
4. стенд: остановлен (`stand.sh stop N`) или оставлен и почему.
```

Основная сессия после отчёта: `git log <ветка>..stand/tN`, ревью, merge/cherry-pick,
`stand.sh rm N --delete-branch`.

Сколько агентов: параллелить только независимые модули/задачи; каждый стенд ~1 ГБ памяти и
свои ядра на тесты — на типовой машине 2–3 стенда одновременно.
